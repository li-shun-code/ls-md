# Domain Docs

## Before exploring

Read the root `GLOSSARY.md`, or `GLOSSARY-MAP.md` if it exists, and relevant decisions under `docs/adr/`. If these files do not exist, proceed; domain modeling creates them when useful terms or decisions are resolved.

## Layout

This is a single-context repo. Keep the glossary at the root and ADRs under `docs/adr/`.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests. If a needed term is missing or conflicts with current usage, resolve it through domain modeling. Flag output that conflicts with an existing ADR instead of silently overriding it.
